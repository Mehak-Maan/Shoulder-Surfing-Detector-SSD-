1. Executive Summary

In shared modern working environments—including open-plan corporate offices, coworking spaces, cafes, and academic computer laboratories—visual eavesdropping (conventionally termed Shoulder Surfing) remains an insidious, pervasive physical security vulnerability. Attackers routinely extract high-value intellectual property, sensitive system source code, passwords, and private communications simply by looking over an authorized user's shoulder.

The Shoulder Surfing Detector (SSD) is a computer-vision powered, privacy-first cybersecurity utility designed to eradicate this physical attack vector. Operating locally via standard USB or integrated laptop webcams, the system continuously analyzes spatial occupancy, isolates the registered owner from passersby using head pose heuristics and encrypted biometric embeddings, and executes a graduated defensive escalation ladder (Toast Notification → Fullscreen Gaussian Blur Overlay → OS Desktop Lock). The software runs entirely on standard CPUs without requiring GPU acceleration or network access, ensuring sub-millisecond per-frame latency and zero external data exposure.

3. Core Technical Modules & Algorithmic Design

3.1 Camera Anti-Tamper & Health Monitoring (camera_health.py)

Adversaries may attempt to bypass optical monitoring by covering the lens with opaque objects or injecting static frozen frames. The system implements continuous statistical anomaly detection:

  • Covered / Dark Lens Detection: Evaluates mean luminance (μ ≤ 12.0 / 255) and standard deviation (σ ≤ 6.0). A camera obstructed by tape or cloth flags a covered event after 2.0 continuous seconds.
  • Frozen Video Stream Detection: Computes inter-frame normalized pixel difference (Δdiff ≤ 0.05). If identical frames persist beyond 3.0 seconds, a stream fault is declared.
  • Fault Containment Policy: Depending on operational security policy, a camera fault triggers immediate automated protection (warn, blur, or system lock).

3.2 Dual-Pass Face Detection with Far-Field Tiling (detector.py)

Standard face detection models fail on small faces located beyond 2 meters. SSD Phase 4 implements an innovative dual-pass inference engine:

  • Near-Field Pass: Downscales input frames to 640 px width, processing immediate workstation users with minimal CPU cycles.
  • Far-Field ROI Tile Passes: Partitions the upper normalized region [0.0, 0.0, 1.0, 0.7] into an overlapping 3×2 grid. Each tile is evaluated in high native resolution, extending the detection horizon up to 3.5 meters behind the workstation without incurring full-resolution frame overheads on every frame.

3.3 Spatial Multi-Object IoU Tracker (detector.py)

Associates bounding boxes across time using Intersection over Union (IoU) with a threshold of 0.20 and a normalized Euclidean centroid fallback. Bounding box coordinates are stabilized via an Exponential Moving Average (EMA, α = 0.5) to suppress visual jitter. Tracks persist across short occlusions with a 0.6 s time-to-live (TTL).

3.4 Gaze & Attention Estimation (gaze.py)

To eliminate false alarms caused by innocent coworkers walking past without looking at the display, head pose is calculated trigonometrically from the 6 BlazeFace facial keypoints (right eye, left eye, nose tip, mouth center, and ear tragions):

Head Yaw Formula:
Yaw Ratio = |x_nose - (x_left + x_right) / 2| / |x_left - x_right|
Yaw Angle = arcsin(min(1.0, Yaw Ratio / 0.6)) × (180° / π)

A coworker turned away (> 55° yaw) is filtered out. An 8.0° hysteresis barrier ensures that minor head motions near the threshold do not cause state flapping.

3.5 Biometric Enrollment & Privacy Architecture (identity.py, enrollment.py)

Rather than naively assuming "the largest face is the owner", Phase 4 introduces local biometric verification:

  • One-Time Interactive Enrollment: Running main.py --enroll captures 20 verified frontal face embedding vectors at 0.5 s intervals while guiding the user.
  • Affine Face Alignment: Transforms detected facial geometry such that eye centers lie horizontal at fixed inter-pupillary scale, neutralizing head-tilt variations.
  • Zero Raw Images at Rest: Facial pixel crops are embedded and immediately purged from memory. Embeddings are stored on disk encrypted via Fernet (AES-128-CBC + HMAC-SHA256) with OS-restricted file permissions (0600).

4. Progressive Defensive Escalation Ladder

The system state machine utilizes monotonic wall-clock elapsed time (seconds) rather than frame counts to ensure deterministic behavior across varied hardware:

LOCKED Persists + 4.0 s OS Workstation Lock (Win+L) Complete session termination; requires user re-authentication.

7. Operational Deployment & User Interface

Two production-ready operational modes are provided:

  1. Interactive GUI Mode (run_gui.bat): Visual debugging window showing live camera frames, color-coded bounding boxes (Green = Owner, Red = Intruder), head pose angles, and live FPS counters. Includes hotkeys: q (quit), d (toggle debug vectors), t (track IDs), space (pause).
  2. Stealth Background Service (run_background.bat): Runs silently via pythonw.exe with zero terminal footprint. Places a lightweight control icon in the Windows Taskbar Notification Area (System Tray) allowing instant pause, resume, and shutdown.
